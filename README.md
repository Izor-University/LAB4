# LazySequence Framework

[![C++ Standard](https://img.shields.io/badge/C%2B%2B-17-blue.svg)](https://isocpp.org/)
[![CMake](https://img.shields.io/badge/CMake-3.14%2B-green.svg)](https://cmake.org/)

**LazySequence Framework** — это высокопроизводительная библиотека на языке C++ для работы с трансфинитными (бесконечными) ленивыми последовательностями, абстрактными потоками ввода-вывода и генераторами статистических данных.

Основой математического аппарата проекта служит арифметика ординалов Кантора, позволяющая корректно оперировать бесконечными структурами данных.

---

## Архитектура проекта и назначение компонентов

Архитектура системы разделена на пять уровней с однонаправленными зависимостями. Каждый класс решает строго определенную задачу (Single Responsibility Principle).

### 1. Базовые абстракции (папка `core/`)
*Примечание: Большинство структур данных в данной директории (например, `Sequence`, `MutableArraySequence`, `BitSequence`) унаследованы из Лабораторной работы №2. Уникальным нововведением для текущего проекта является класс `Ordinal`.*

*   **`Ordinal.hpp`**: Математическое ядро системы. Реализует арифметику ординалов Кантора вида $\omega \cdot k + n$. Класс переопределяет операторы сравнения, левого сложения (с поглощением конечных смещений) и левого вычитания. Служит заменой стандартному типу `int` для индексации элементов за пределами бесконечности.
*   **`Option.hpp`**: Контейнер `Option<T>` (Try-семантика), инкапсулирующий либо наличие значения (`Some`), либо его отсутствие (`None`).
*   **`Sequence.hpp`**: Абстрактный полиморфный интерфейс для всех линейных коллекций в проекте.
*   **`MutableArraySequence.hpp`**: Физический динамический массив. В контексте текущего проекта используется исключительно как низкоуровневый контейнер для кэширования элементов.

### 2. Вычислительная логика (папка `generators/`)
Данный слой отвечает исключительно за вычисление элементов. Классы этого слоя не имеют состояния (stateless) и не кэшируют данные.

*   **`IGenerator.hpp`**: Абстрактный интерфейс, реализующий паттерн **Strategy**. Определяет метод `Option<T> Generate(const Ordinal&)`, который позволяет вычислить элемент по его многомерной координате.
*   **`FunctionGenerator.hpp`**: Базовый генератор, вычисляющий элементы на основе переданного указателя на математическую функцию $f(x)$.
*   **`SmartDataGenerator.hpp`**: Статистический движок. Генерирует псевдослучайные значения (тип `double`) с заданными параметрами. Равномерное распределение строится на базе детерминированного алгоритма LCG. Нормальное (гауссовское) распределение вычисляется через метод Ирвина-Холла (аппроксимация суммы равномерно распределенных величин).
*   **`Decorators.hpp`**: Коллекция классов, реализующих паттерн **Decorator**. Каждый класс принимает указатель на базовый генератор (`baseGen`) и модифицирует его поведение:
    *   `AppendGenerator`: Перехватывает индекс, равный длине базовой последовательности, и возвращает заданный элемент.
    *   `PrependGenerator`: Выполняет правый сдвиг индексов Кантора, освобождая нулевой индекс для нового элемента.
    *   `InsertAtGenerator`: Комбинирует транзитный пропуск индексов до точки вставки и сдвиг Кантора для индексов после нее.
    *   `ConcatGenerator`: Объединяет две последовательности. Осуществляет маршрутизацию запросов с применением левого вычитания ординалов для вычисления локального индекса правой части.
    *   `InterleaveThreeGenerator`: Выполняет чередование трех последовательностей ($a_0, b_0, c_0, a_1...$) с использованием математических операций по модулю (`n % 3`).
    *   `MapGenerator`: Применяет функцию отображения к результату базового генератора.
    *   `WhereGenerator`: Осуществляет условный поиск элементов (фильтрацию), последовательно опрашивая базовый генератор до совпадения с заданным предикатом.
    *   `SubsequenceGenerator`: Создает срез, прибавляя стартовое смещение к каждому запрашиваемому индексу.

### 3. Оркестрация и управление памятью (папка `sequences/`)
*   **`LazySequence.hpp` / `.tpp`**: Главный класс-контейнер, связывающий математику, правила генерации и физическую память.
    *   Выступает владельцем полиморфного указателя `IGenerator`.
    *   Реализует **двумерную мемоизацию (2D-кэш)**. Первое измерение массива отвечает за счетчик бесконечностей $\omega$, второе — за конечное смещение. Это гарантирует время доступа $O(1)$ для ранее запрошенных элементов и предотвращает переполнение памяти при трансфинитных скачках.
    *   Реализует функциональные операции (`Map`, `Where`, `Concat`), которые создают новые ленивые последовательности за константное время $O(1)$, сохраняя иммутабельность исходного объекта.

### 4. Навигация и абстракции ввода-вывода (папка `streams/`)
*   **`LazyInputStream.hpp`**: Поток последовательного чтения. Инкапсулирует внутренний курсор типа `Ordinal`. Позволяет читать элементы один за другим, а также выполнять команду `Seek()` для трансфинитных скачков (например, мгновенного перемещения на координату $\omega$).
*   **`LazyOutputStream.hpp`**: Поток последовательной записи. Выполняет роль менеджера состояний и сборщика мусора. При вызове метода `Output()` поток оборачивает исходную ленивую последовательность в новый декоратор и **автоматически освобождает память** устаревшей версии объекта, защищая систему от утечек (Memory Leaks).

### 5. Пользовательское представление (папка `ui/` и `main.cpp`)
*   **`ConsoleUI.hpp` / `.cpp`**: Интерактивный REPL-интерфейс командной строки. Реализует безопасный цикл чтения команд с очисткой входного буфера. Инкапсулирует глобальное состояние (массивы указателей на регистры). Выводит визуальный дашборд с предварительным просмотром элементов в каждом регистре.
*   **`main.cpp`**: Чистая точка входа, инициализирующая и запускающая `ConsoleUI`.

## Основные архитектурные решения

### 1. Принцип Иммутабельности и Делегирования
Ни одна операция над ленивой последовательностью не изменяет ее физическое содержимое. Вместо этого выстраивается древовидная структура декораторов. Декораторы не хранят собственные массивы данных; при получении запроса индекс маршрутизируется вглубь структуры ("сверху вниз"), а результаты последовательно модифицируются на этапе возврата ("снизу вверх").

### 2. Динамическое усечение длины (Try-семантика)
Все генераторы возвращают объект `Option<T>`. Это позволяет безопасно интегрировать систему с непредсказуемыми источниками данных (например, прерывающимися потоками сетевых сокетов). Если базовый генератор исчерпан и возвращает `Option::None()`, класс `LazySequence` перехватывает данный сигнал и с помощью `const_cast` динамически усекает свою изначально заявленную бесконечную длину ($\omega$) до фактического количества вычисленных элементов.

### 3. Строгий контроль динамической памяти
Библиотека разработана без использования механизмов автоматического подсчета ссылок. Управление памятью обеспечивается через:
1.  **Паттерн Prototype:** Каждый декоратор использует полиморфный метод `Clone()` для создания собственной глубокой копии базового генератора.
2.  **Правило Трех:** Класс `LazySequence` гарантирует каскадное удаление дерева декораторов и двумерного кэша через явно определенный деструктор, конструктор копирования и оператор присваивания.

## Инструкции по сборке и запуску

Проект использует систему сборки **CMake** (минимальная версия 3.14). Для компиляции модульных тестов используется библиотека Google Test, которая интегрирована через механизм `FetchContent` и будет загружена автоматически.

### 1. Генерация конфигурации и сборка
Откройте терминал в корневой директории проекта и выполните следующие команды:

```bash
# Генерация файлов сборки
cmake -B build

# Компиляция проекта (собирает библиотеку ядра, тесты и UI)
cmake --build build
```

### 2. Запуск пользовательского интерфейса (CLI REPL)
Главное приложение-дашборд компилируется в цель `app`. Запуск производится следующей командой:

```bash
# Для Linux/macOS
./build/app

# Для Windows
build\Debug\app.exe
```

### 3. Запуск модульных тестов
Система содержит исчерпывающее покрытие модульными тестами (алгебра ординалов, функциональные декораторы, статистические распределения и проверка отсутствия утечек памяти). Тесты компилируются в цель `run_tests`.

```bash
cd build
ctest --output-on-failure
```
Альтернативный вариант — прямой запуск исполняемого файла тестов: `./build/run_tests` (или `build\Debug\run_tests.exe` для Windows).
